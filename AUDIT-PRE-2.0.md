# Финальный аудит перед разработкой High. 2.0

27.09.2026. Проверена текущая ветка приложения High. в `outputs/Vyshe`, не отдельный сайт PMP. Это аудит конкретных сценариев и исправлений, а не гарантия отсутствия любых ошибок.

## Исправлено

| Область | Ошибка | Исправление и доказательство |
| --- | --- | --- |
| Синхронизация | Облачная версия могла заменить другой/изменённый за время запроса локальный график | Перед применением сверяются ID и ревизия снимка; замена проходит через общую очередь сохранений. Проверки изменённой ревизии, смены/закрытия графика. |
| Синхронизация | Сохранение скачанного снимка меняет локальную revision/updatedAt; повторный sync ошибочно показывал конфликт | Решение учитывает независимые локальную и серверную ревизии маркера. Если ни одна не изменилась, повторная синхронизация — no-op. |
| Синхронизация | Успешный HTTP-ответ мог считаться сохранением без подтверждения нужного ID/ревизии; ID внутри скачанного снимка проверялся не во всех путях | Общий клиент проверяет подтверждение PUT и ID расшифрованного дневника. Некорректные ответы отвергаются. |
| Сеть | Зависший fetch/body оставлял синхронизацию ждать без ограничения | AbortController ограничивает весь запрос 30 секундами; сообщение допускает повтор. Проверен timeout и последующий успешный retry. |
| Сервер | Без Content-Length тело полностью читалось до проверки размера | Worker ограничивает поток входящего запроса 1 800 000 байт; oversized-запрос без заголовка получает 413. Изменение Worker пока только в исходниках. |
| Числовое поле | Набор `-0.2` превращался в положительное число, потому что `-0` нормализовался раньше окончания ввода | Во время редактирования сохраняется знак нуля. Проверены последовательный ввод и кнопка минуса при значении 0. |
| Обновления | Повторные нажатия и фоновая проверка могли пересекаться с загрузкой/установкой | Операции сериализованы, загруженное предложение сохраняется; повторный install не запускает вторую установку. |
| Закрытие | Native close ожидал очередь хранилища, но не UI-операции, которые ещё не передали запись в хранилище | Закрытие и обновление ожидают стабильного завершения очереди UI, затем диска. Тест удерживает UI-сохранение и проверяет файл перед командой close. |
| Windows release CI | Ручной git fetch без токена перестал работать с приватным репозиторием; триггер не включал 2.0 | Стандартный авторизованный checkout без сохранения credentials, теги v1.9.* и v2.*. Публикация нового релиза во время аудита не запускалась. |
| Android CI | setup-android запрашивал исчезнувший пакет SDK `tools` | После реального падения run 36320817610 задан `packages: platform-tools`; последующий ручной workflow успешно собрал APK без публикации релиза. |
| Архив | Повреждённый или null JSON старого удалённого графика блокировал запуск исправного дневника | Очистка пропускает повреждённый файл, сохраняя его и marker удаления. Проверены оба случая, отсутствие в восстановлении и сохранность текущего графика. |
| Android | Desktop updater permissions и minimize/maximize не поддерживаются мобильным target | Отдельная desktop capability и cfg(desktop). После трёх воспроизведённых ошибок собран debug APK: [run 36321907343](https://github.com/x1pee/High./actions/runs/36321907343), commit 1e09ee6. |
| QA | UI-тест ожидал неверную предпоследнюю версию истории | Ожидание исправлено с 1.9.9.17 на существующую 1.9.9.18. |

Исходники исправлений: `bcaa7e8`, `3ef67cc`, `29d95f2`, `1e09ee6`. Отдельный план реализации обновлений/синхронизации: [V2-READINESS.md](V2-READINESS.md).

## Проверки и границы доказательств

- `npm test`: 126/126. Модель OHLC и процентов, сохранение/восстановление/архив, интервалы и часовые границы, quick moves, подписи манифеста, синхронизация и жизненный цикл обновления.
- `cargo test --locked`: 2/2. Атомарная замена файла и ограничение путей профиля. Desktop-команды окна отделены от мобильного target через cfg(desktop).
- `npm audit --audit-level=moderate`: 0 известных уязвимостей по ответу npm на дату проверки. Это не заменяет аудит всего native dependency tree.
- `npm run qa:tauri:layout`: PASS на 1440×960 и 390×844. Проверены формы, ввод отрицательного дробного числа, quick-move анимация, Auto, вертикальное/горизонтальное перемещение, пространство будущего, линии/стрелка/вертикаль, undo, история релизов, настройки и отсутствие горизонтального переполнения. Скриншоты просмотрены. Native IPC в этом тесте имитирован.
- Локальная интеграция двух отдельных GraphLibrary с настоящей логикой Worker и SQLite-адаптером D1: зашифрованный обмен, сохранение прежнего локального графика, перезапуск, конкурентные правки, HTTP 409, сохранность обеих сторон конфликта. Это не тест двух физических устройств и не загрузка в рабочую облачную базу.
- `npm run pack` с `VYSHE_INSTALLED_BUILD=1`: Windows EXE собран без установщика.
- `npm run qa:tauri`: PASS в настоящем WebView2: создание/запись, сохранность после перезапуска, ограничение native IO, видимое ручное открытие, автозапуск в трей, повторный запуск поднимает окно, корректное закрытие, сохранённый английский язык после полного перезапуска и неизменные русские пользовательские записи. Для теста использованы отдельный профиль и временный identifier `life.high.audit20260927`, поскольку пользовательская старая копия уже запущена. Функциональный код тот же; это не тест обновления установленной пользовательской копии.
- Live read-only: GitHub API подтвердил private=true и последний релиз v1.9.23 с EXE, подписью и latest.json; curl подтвердил анонимный HTTP 404 для манифеста. Cloudflare health вернул ok=true/protocolVersion=1. Секреты и реальные дневники не отправлялись в тестовую базу.
- Проверенная native-сборка с audit identifier: SHA256 `8F2937BC889782A85299E9AB45A42D70A7297BD1FB80883760031916A1498F2F`, изолированный профиль `work/tauri-native-profile-HpBBx5`. Обычный preview EXE собирается отдельно с прежним production identifier.
- `git diff --check`: без ошибок пробелов.

Unit и layout QA запускаются последовательно: оба готовят общую папку tauri-dist. Их одновременный запуск во время аудита дал артефакт гонки сборки (неподставленная версия); последовательный прогон прошёл. Не запускать эти команды параллельно с упаковкой той же папки.

По дополнительному запросу добавлен сохранённый выбор RU/EN на первом экране и в настройках оформления. Локализуются статические части шаблонов, а пользовательские значения не проходят через словарь. Переведены интерфейс, график, формы, настройки, 500 примеров, быстрые движения и подсказки. Даты и числа используют выбранную локаль.

`node scripts/website-screenshots.mjs`: PASS — основные экраны, все пять вкладок настроек, история версий, переключение EN→RU→EN с перезагрузкой, неизменность событий и ширина 390px. Native IPC имитирован; снимки показывают реальный frontend с отдельным демонстрационным дневником. `node scripts/website-cards.mjs` создаёт три карточки 2400×1600 и WebP, исходные снимки 3200×2100 сохранены в raw/.

Android CI PASS относится к коммиту перед локализацией; сборка APK с переводом отдельно не проверена.

## Что ещё закрывает выпуск 2.0

1. Авторизованный канал приватных GitHub Releases ещё не реализован. Прежняя анонимная схема действительно недоступна; исторический успешный updater-тест до приватизации этого не меняет.
2. Текущие ключи сопряжения хранятся в WebView localStorage; нет QR-подключения с подтверждением, отдельных отзываемых ключей устройств, фоновой очереди и синхронизации удаления целых графиков.
3. Физические Android-устройства, их клавиатуры/файловые диалоги/фоновые переходы и установка обновления APK ещё не проверены. Браузер и CI-сборка не заменяют эти проверки.
4. Linux/macOS runtime в этом аудите не проверялся. Android debug APK не предназначен для конечного релиза.
5. Рабочий релиз v1.9.23 не заменялся. Исправления находятся в ветке разработки; версия 2.0 не опубликована. Worker-изменение потребует отдельного deploy вместе с проверкой нового сервиса.

Подробные этапы, поведение при конфликтах и критерии допуска платформ описаны в плане 2.0. В первую очередь — приватное обновление и защищённое сопряжение; затем Windows ↔ Android на физическом устройстве и тест обновления поверх предыдущей версии.
