# Актуальная архитектура · 1.9.9.19

Приложение собрано на Tauri 2. Интерфейс и расчёты находятся в `src/`; `src/tauri-bridge.mjs` адаптирует их к native IPC, а Rust команды ограничивают доступ профилем и атомарно сохраняют JSON. `desktop/library.cjs` оставлен как общий код библиотеки графиков; Electron shell используется только для совместимости данных. Установленная desktop-версия подключает Tauri updater и process plugins.

На Windows дневник хранится в `%APPDATA%\Vyshe`. Версия продукта из `package.json.appVersion` подставляется в UI; Cargo/Tauri использует трёхчастную SemVer. Установленная Windows-версия проверяет Tauri updater по GitHub Release и устанавливает обновление после подтверждения. Переносная EXE отключает updater. Подписанный релиз собирает `.github/workflows/updater-release.yml`; завершённый end-to-end тест требует отдельной начальной и целевой установок.

Реальный объём — сумма модулей изменений; пустые переходы отделяются нейтральным цветом. Избранные даты валидируются и хранятся в дневнике, а сводки недели/месяца выводятся из фактических записей без изменения модели событий.

# Историческая архитектура Electron · 1.9.9.4 и ранее

`desktop/application.cjs` владел preferences.json, треем, Windows autostart/shortcut и electron-updater. Renderer имел только фиксированные IPC-методы. Сборка NSIS per-user больше не используется; этот раздел ниже сохранён как история предыдущей оболочки.

GraphLibrary.trash/restore/purgeExpired сериализованы с сохранениями. Снимок удаления имеет срок 30 дней от mtime атомарно созданного файла. Старые снимки 1.9.5 используют тот же mtime. После истечения остаётся tombstone; резервное восстановление journal.json не отменяет удаление.

Импульс события — временный SVG поверх реальной свечи, от event.before до event.after. По завершении восстанавливается настоящий OHLC, график/события не мутируются. Отдельные будущие записи разрешены UI после трёх подтверждений; верхняя граница просмотра учитывает их, периоды статистики остаются календарными относительно сегодня.

Ниже — архитектура предыдущих версий; новые решения выше имеют приоритет.

# Архитектура и продолжение на iPhone и Android

## Границы

1. `domain.mjs`: проверка схемы, локальная дата, запись событий и дней, OHLC, итог и проценты, компактный снимок виджета. Не зависит от Electron и DOM; работает в JavaScriptCore, Node и браузерной среде с `crypto.randomUUID` / `structuredClone`.
2. `intraday.mjs`: производная визуализация. Функция принимает дневные реальные события и возвращает свечи. Не мутирует исходный дневник. Её результат не должен синхронизироваться и попадать в реальные финансово-подобные показатели.
3. `app.mjs`: интерфейс и управление экраном. Общается с хранилищем только через узкий preload API.
4. `JournalStore`: валидируемая очередь сохранений, контроль ревизий, атомарная замена файла, резервные копии, восстановление. В мобильной версии этот адаптер заменяется, математическая модель сохраняется.

## Модель версии 2

График: UUID, schemaVersion, revision, createdAt/updatedAt UTC, settings, events, days. Записи: стабильный UUID, createdAt/updatedAt, deletedAt (tombstone), локальная календарная date. У события есть время HH:mm, order, text, delta. Порядок — локальная дата, время, order, UUID; order разрешает несколько записей одной минуты. Перестановка в UI обменивает время и order соседей.

Дата и время — **локальные пользовательские координаты дневника**, не UTC-время происшествия. Они намеренно не пересчитываются при путешествии. `settings.timeZone` сохраняет исходный пояс дневника; `createdAt` и `updatedAt` служат метаданными записи, а не заменой пользовательской даты. Будущая мобильная версия должна сохранить эту семантику. Не пытайтесь выводить физический порядок одновременных событий из локальной даты в дни перевода часов.

Импортированные ранние записи schemaVersion=1 без time получают 12:00 и существующий order. Отсутствующее interpolate мигрирует в true. Неизвестные версии схемы отклоняются; будущие миграции должны быть явными и тестироваться на экспортированных файлах.

Баллы хранятся с точностью до сотых. Каждое суммирование округляется до сотых. Процент вычисляется от абсолютного значения базы; при нуле возвращается null. В UI null отображается как «—». Событие хранит unit: points | percent и delta как введённое число. calculate() возвращает inputValue и вычисленную delta в баллах. Проценты вычисляются от абсолютного значения перед событием; при изменении прошлого пересчитываются. Schema 1 мигрирует в schema 2 с unit=points, сохраняя старые суммы. Цепочка с итогом вне ±1e15 отклоняется до записи.

## Контракт синхронизации

`sync-contract.d.ts` определяет `SyncTransport.pull/push`, envelopes и конфликты. Это контракт будущего адаптера, а не фиктивная действующая синхронизация. Для первой сетевой реализации необходимо:

- Создать deviceId, серверный журнал изменений и отдельный устойчивый outbox. Локальная revision текущего JSON — не глобальная серверная версия.
- Отправлять записи и tombstones по UUID, повторные доставки обрабатывать идемпотентно.
- Для каждой записи хранить baseRecordVersion, возвращаемую сервером. Настройки передавать отдельной версионируемой записью; локальные тема/анимация могут оставаться настройками устройства.
- Изменения разных UUID объединять. Одновременные правки одного UUID относительно общей базы возвращать как конфликт и сохранять обе версии до выбора пользователя. Не терять текст по правилу «последняя дата победила»; часы устройств могут расходиться.
- Удаление против редактирования тоже считать конфликтом. Tombstones не удалять до подтверждения всеми активными устройствами / серверного безопасного горизонта.
- В одном применении пакета проверять дату, порядок и уникальность заметки на дату; конфликты порядка и две заметки одного дня разрешать явно.
- После принятия пакета валидировать весь дневник, сохранять одной транзакцией, пересчитывать свечи и обновлять виджет. Незавершённая сеть не должна блокировать локальный ввод.

## Виджет

`widgetSnapshot(journal, date)` выдаёт schemaVersion, graphId, name, date, timeZone, value, delta, percent, recorded, series (до 30 последних реальных дневных итогов), updatedAt. Будущая iOS-оболочка может записывать JSON в App Group для WidgetKit. Виджет показывает реальные данные, никогда не интерполяцию. План обновления WidgetKit и реакция на входящие изменения требуют реализации на iPhone; сейчас их нет.

## Безопасность оболочки

Локальный `vyshe://app` protocol, sandbox, contextIsolation, отсутствие Node в renderer, ограниченный preload, валидация IPC sender, запрещённые всплывающие окна и навигация. CSP запрещает удалённые соединения и внешние скрипты. Текст пользователя экранируется перед рендерингом. Файловые пути выбирает главный процесс через системные диалоги, размер импорта ограничен 32 МБ. Основой послужили [официальные рекомендации Electron](https://www.electronjs.org/docs/latest/tutorial/security).

## Ограничения первой версии

Несколько локальных графиков; в каждом 100 000 событий максимум, 50 000 заметок, диапазон дат 1900–2200, значение старта до ±1 млрд и изменение одного события до ±10 млн. Автокопии — последние 30 состояний, не бесконечный журнал. JSON не зашифрован. Синхронизация и доставка виджетов отсутствуют. Windows EXE без цифровой подписи.

## Перенос на iPhone и Android · 1.2

`JournalTransferV2` в `sync-contract.d.ts` описывает текущий переносимый JSON: события, заметки, UUID, удалённые записи, локальные даты/время и настройки. UTF-8, кириллица и emoji сохраняются. Это тот же формат, который уже экспортирует десктоп: будущим мобильным клиентам не нужен отдельный Windows-конвертер. Поле `SyncEnvelope.platform` допускает windows/ios/android. Серверный протокол остаётся заготовкой.

В `settings.appearance` необязательно сохраняются palette, basePalette и четыре HEX-цвета. Файл без appearance использует «Полночь» (amber) в тёмной теме и синюю палитру в светлой; поле не требует смены schemaVersion. `themes.mjs` содержит общую чистую функцию выбора палитры и проверки цветов. Настройки оформления входят в файловый перенос; в будущей сетевой синхронизации пользователь должен отдельно решить, синхронизировать ли оформление устройств.

Для Swift/Kotlin нужно реализовать эквивалентную валидацию `domain.mjs` и подтвердить одинаковые результаты на общих JSON-наборах; для JS-оболочки модель может использоваться напрямую. Мобильный импорт должен сначала проверять весь файл, показывать пользователю сводку, сохранять копию текущей базы и заменять её одной транзакцией. Даты YYYY-MM-DD и время HH:mm остаются пользовательскими координатами, без сдвига часового пояса. Decimal-баллы следует вычислять в сотых или с совместимым округлением, а не рассчитывать их по интерполяции.

Для Android предусматривается локальный адаптер хранения и виджет AppWidget/Glance, читающий тот же `widgetSnapshot`, что будущий WidgetKit на iOS. Виджет не открывает сетевой транспорт самостоятельно и отображает только подтверждённые реальные итоги. Реальных мобильных приложений, регистрации, сервера и фонового обмена пока нет. Проверка JSON туда-обратно на десктопе подтверждает сохранность структуры, но не заменяет тест на устройствах.

## Интерактивные исправления · 1.3

Без событий внутри выбранного дня `intraday` возвращает пустую серию. Интерполяция остаётся производной только от реальных наблюдений, а не генератором движения для пустой базы.

Изменения оформления передаются в очередь через функцию, получающую актуальный дневник на момент записи. Обычная форма сохраняет последнюю записанную палитру; счётчик изменений содержимого отклоняет устаревшие конкурирующие формы. Смена личного/демонстрационного графика ждёт завершения очереди. Изменения темы в демо не пишутся в личный файл.

`event-examples.mjs` содержит 500 локальных текстовых подсказок без оценок. Форма не закрывается по backdrop/cancel, дата и время хранятся в прежнем формате. Для «Сейчас» значение уточняется непосредственно перед записью.

## Библиотека графиков · 1.4

GraphLibrary сериализует создание, переключение и сохранение. journal.json остаётся активным файлом с прежним механизмом восстановления. Перед переключением текущий график атомарно архивируется в graphs/<sha256(id)>.json. Список объединяет архивы с текущим состоянием; активный файл имеет приоритет. Некорректные неактивные архивы не удаляются и не показываются в списке. Сбой записи оставляет текущий файл и ревизию неизменными. Все графики используют общие последние 30 резервных копий; экспорт сохраняет один активный график.

Тестовые записи имеют test=true; удаление создаёт tombstones. Будущие мобильные адаптеры должны поддерживать schemaVersion=2 и unit, иначе процентное намерение потеряется. SyncEnvelope привязан к graphId; сетевого сервера по-прежнему нет.

## Непрерывная шкала · 1.5

`timeline.mjs` собирает календарный диапазон из вычисленных дневных свечей и `intraday`, включая нейтральные промежутки. Координаты date/minute переводятся в условные UTC-минуты, чтобы переходы DST не удаляли пользовательское время; это координатная сетка, а не реальные UTC-времена событий. Интервал и длина окна независимы. Лимит 2400 интервалов ограничивает затраты SVG; крайняя частичная свеча может добавить один элемент.

Дневные итоги, исходные записи и схема 2 остаются прежними. Средняя линия, измерение, процентная ось и автоматические названия — только представление. MA использует отображаемые закрытия (включая интерполяцию), измерение сравнивает закрытия выбранных свечей. Названия имеют пять порогов абсолютного процента: <0.3, <1, <3, <7 и >=7. При нулевой базе выбирается минимальный уровень без выдуманного процента; пользовательский заголовок приоритетен.

Быстрая заметка использует тот же upsertDay и очередь сохранений, что полная форма; временные черновики разделены по graphId/date и не синхронизируются. Генератор тестов создаёт шесть событий в разных четырёхчасовых слотах предыдущего дня. Никаких фоновых, будущих или сетевых событий нет.

Граница наблюдений observedEnd отделена от границы видимого окна end: перенос окна не меняет опорные значения уже записанной истории. На текущем дне наблюдения ограничены текущей минутой.


## Единая панель · 1.6

`calendar-bars.mjs` объединяет полный календарный диапазон в недельные/месячные/квартальные/годовые OHLC. Левая граница расширяется до начала календарного периода, правая не выходит за выбранный день. Даты событий сохраняются; исходные записи не меняются. Размер свечи выбирается только через TIMEFRAMES, видимый диапазон регулируется масштабированием и перемещением. Годы на длинных интервалах подписываются явно.

Разметка хранится в renderer Map по graphId только до закрытия приложения. Уровень привязан к абсолютному значению, тренд — к двум парам времени/значения. SVG-проекция пересчитывается при изменении масштаба, интервала и размера окна; clipPath обрезает рисунки по области графика. Магнит выбирает ближайшее значение OHLC. Эти данные не входят в переносимый журнал и не меняют schema 2.

`more-examples.mjs` добавляет 250 оригинальных подсказок к прежним 250. Fisher–Yates перемешивает копию каталога при раскрытии, предотвращает немедленный повтор первого примера; фильтры не перемешивают результаты во время ввода. 100 названий свечей детерминированы датой и величиной изменения.


## Выбор и представление · 1.7

`chart-view.mjs`: геометрический hit-test тела и тени свечи, засечек OHLC или отрезка линии с допуском 5 CSS px. Нейтральные пропуски не интерактивны. Mouse down/up должны попасть в одну свечу; пустой клик снимает закрепление, drag перемещает историю. Измерение также требует попадания в свечу. Исходный массив visible отделён от visualBars.

Heikin Ashi: close=(O+H+L+C)/4, open=(previous HA open+previous HA close)/2; первая свеча использует (raw open+raw close)/2. High/low включают raw экстремумы и HA open/close. Дни без наблюдений нейтральны и сбрасывают рекурсию. Для стабильного перемещения используется до 96 предшествующих интервалов; средняя прогревается 28 предшествующими. Основной ярлык значения и карточки остаются исходными; измерение и BNA работают по отображаемым закрытиям. Разметка не меняет дневник.

`tool-help.mjs` размещает общую подсказку в body и ограничивает её границами окна, поддерживает hover/focus/Escape; native title удаляются. Меню видов также вынесено из прокручиваемой панели инструментов. BNA period 7/14/28 хранится в localStorage профиля, с проверкой допустимых значений; не относится к переносимым данным. noteSelection разделяет явно выбранный день и автоматическое перемещение тестовой истории, привязан к graphId и сеансу.


## Компоновка и несколько средних · 1.8

`panel-layout.mjs` отвечает за локальную высоту/положение ленты, ограничение размеров, указатель и клавиатуру. ResizeObserver отключается при перерисовке. Настройки живут в localStorage; они не изменяют переносимый дневник. При малом окне разделитель скрывается, чтобы сохранить доступ к содержимому.

BNA хранит выбранный набор 7/14/28; выключение BNA временно скрывает набор. Миграция читает прежний одиночный период. Цвета имеют отдельные токены для тёмной/светлой темы. Средние не используют календарные периоды до первой записи и не отображаются до накопления полного периода.

`autoRange` включается при сбросе/смене интервала и снимается ручной навигацией. На календарном графике Авто обрезает прошлое до начала истории; для недельных и больших интервалов шаг ограничен 32px. `candleLeft` задаёт начало размещённой серии отдельно от левого края сетки; hit-test и рисование учитывают это смещение. Геометрия оси и данные дневника остаются раздельными. Метки времени измеряются после построения SVG, ограничиваются областью и прореживаются при пересечении.

Подписи к короткой истории предлагают дневной интервал, а не синтетические месяцы. Белые маркеры событий удалены из рендера и hit-test; данные карточек не затронуты.


## Причинная интерполяция и выбор · 1.9

В `intraday` каждая группа событий одной минуты создаёт две опоры: before в начале минуты, after в конце. Переход внутри минуты линейный (или ступенчатый без сглаживания), соседние промежутки колеблются вокруг неизменного уровня. Одинаковая минута объединяет первый before и последний after, extrema включают before/after каждого события. Это устраняет перенос будущего веса в прошлую свечу, не меняя persisted schema 2. Предыдущий алгоритм визуально интерполировал между after и следующим after.

`chart-context.mjs` содержит границы серии synthetic/non-recorded и итоги последних 30/90/180/365 дней. Реальные события подготовлены в хронологическом массиве; карточка ищет соседние записи бинарным поиском. Выделение группы работает только на видимых промежуточных свечах; реальные и отсутствующие наблюдения не входят в группу.

autoRange (подсветка) отделён от autoLayout (замороженная геометрия). Выключение кнопки сохраняет геометрию до ручной навигации, даже при изменении вида или размера. ЛКМ выбирает дату без pinned; ПКМ/кнопка/P управляют pinned отдельно.

Разметка по-прежнему живёт в памяти, отдельно по graphId. История инструментов содержит до 100 снимков рисунков, магнита и скрытия на график; Ctrl+Z восстанавливает снимок или отменяет первую точку. Поля ввода и диалоги исключены. Добавлены arrow/vertical. Указательные события не перехватываются декоративным слоем фокуса.

`panel-layout` хранит желаемую ширину боковой панели вместе с высотой/порядком ленты, ограничивает размеры доступным окном. Уголок меняет обе координаты. MA хранит прежние ключи настроек для совместимости; пользовательское название и цветовые токены исправлены.

## Изменения контракта 1.9.3

`price-policy.mjs` отделяет допустимость новой мутации от чтения старого файла. `assertPriceChange(previous,next)` проверяет начальную базу и after каждого активного события в полной хронологической цепочке. Нижняя граница 0,01; для существующего отрицательного события разрешено только сохранение или улучшение его прежнего after. Проверка вызывается в renderer commit и повторно внутри очереди GraphLibrary.save/create. Импорт с replace и открытие сохранённого графика намеренно не меняют старую историю. validateJournal/calculate продолжают поддерживать отрицательные старые файлы. Интерполяция между положительными якорями не пересекает 0,01.

Необязательные settings: followEvent (по умолчанию true), liveChart (true), eventOrder (newest; альтернативный time), chartDensity (45; также 90/180), baselineLevel (50; также 25/75). settings.coin дополнен rim (classic/solid/segments) и label (до двух Unicode codepoints); старые color/symbol валидны. Сортировка newest использует createdAt и order только для списка дня и не меняет compareEvents/OHLC. Таймер перерисовывает лишь график при смене минуты у живого края, блокируется активным взаимодействием. В настройках плотность применяется при следующем сбросе окна или запуске.

Timeline сохраняет пустые интервалы после первого наблюдения, с realDelta=0 и recorded=false, а не удаляет всё окно. До первого события пустая история не создаётся. Групповая карточка описывает промежуток предыдущей/следующей записи; подсвечивается пересечение с видимым окном.


## Изменения 1.9.4–1.9.5

- `starter.mjs`: metadata `settings.starter {seed, at, remaining}`; чистая функция строит 15-минутный рисунок до первой записи и агрегирует его для внутридневного интервала. Только `upsertEvent` нового обычного события уменьшает remaining; тестовые массовые записи не расходуют его. Он не пересчитывается по числу живых записей и не возвращается при удалении. В JSON нет фиктивных событий; переносится только маленький seed и счётчик. В дневных/календарных интервалах стартовый слой не рисуется. После remaining=0 никакая прежняя стартовая точка не появляется при возврате в историю.
- Ритм передаёт strength=1/4/8 в bridgeValue. UI по умолчанию 4; чистые функции сохраняют default=1. Опорные значения событий и начала/конца дня точные, вся бухгалтерия считает только реальные записи.
- `event-animation.mjs` использует Web Animations после стабилизации геометрии. Анимация до 12 предшествующих промежуточных свечей и свечи события, длительность менее секунды; настройки eventAnimation/reducedMotion и системное уменьшение движения её выключают. Свечи не добавляются в модель. Линия/базовая линия получают отметку результата.
- `chart-volume.mjs`: реальный count=events.length для каждого агрегата; синтетическая высота 1–3 px имеет count=0/decorative=true, стабильна при перерисовке. Никаких денег, баллов или случайных реальных объёмов. showVolume по умолчанию true.
- Превью карточки pointer-events:none, интерактивны только кнопки в шапке. readingCard включает прокрутку; pinned закрепляет. Удалён hover-intent corridor. Групповое выделение не запрещает смену выбранного индекса внутри группы.
- `moment-picker.mjs`: независимые списки даты/времени, скрытые канонические YYYY-MM-DD/HH:mm. До сохранения проверяется будущее время и дата. `signed-input.mjs` блокирует нечисловую вставку/ввод, текст — источник знака, пустые промежуточные состояния разрешены.
- Coin.color принимает enum из 15 пресетов или строгий #RRGGBB; label до 5 Unicode codepoints, SVG текст экранируется. Шесть новых знаков; старые enum по-прежнему валидны.
- appearance.chartColors classic/theme/custom отделяет акцент оболочки от свечей/индекса. Для старого palette=custom без chartColors применяется custom; остальные темы default=classic. Валидация цветов и контраст остались общими.
- GraphLibrary.remove сериализуется с save/open/create. Сначала fsync+rename снимка в deleted-graphs; снимок одновременно служит маркером удаления. Startup дочитывает маркеры и завершает прерванное переключение. list/open/save/create не воскрешают удалённый id. Последний journal.json удаляется только после durable recovery copy. Явный импорт может восстановить такой id. Восстановление всей библиотеки/корзина с кнопкой остаются будущей работой.
