# Выпуск High. 1.9.9.19

GitHub Release `v1.9.23` предназначен для проверки перехода с предыдущей установленной версии через Tauri updater. `package.json.appVersion` задаёт видимую версию 1.9.9.19; внутренняя версия Cargo/Tauri — SemVer 1.9.23. Переносной EXE остаётся отдельным способом запуска без автообновления.

История в окне обновлений строится из последних записей `CHANGELOG.md`. Формат отображаемой версии принимает прежние четыре части (`1.9.9.17`) и обычный SemVer (`2.0.0`), поэтому переход к 2.0 не требует отдельного формата истории.

Запусти EXE двойным щелчком. Ручной запуск всегда открывает полное окно. Дневник и настройки остаются в прежней папке `%APPDATA%\Vyshe`, чтобы переименование не теряло данные. Для замены EXE закрой программу и скопируй новую версию на место старой; данные от этого не перемещаются. Нужен установленный WebView2 Runtime.

## Автоматические сборки и обновления

`.github/workflows/tauri.yml` сохраняет ручные и платформенные сборки. `.github/workflows/updater-release.yml` запускается для SemVer-тегов `v1.9.*`, проверяет JavaScript и Rust, затем публикует Windows NSIS installer, подписанный updater-архив и `latest.json` в GitHub Release. В релизе используются NSIS-артефакты, так что portable EXE не подменяется установщиком.

Updater подключён в Rust и JavaScript, а публичный ключ и endpoint находятся в `src-tauri/tauri.conf.json`. Для выпуска приватный ключ должен храниться только в секрете `TAURI_SIGNING_PRIVATE_KEY` репозитория GitHub Actions; секрет нельзя помещать в исходники или релизные файлы. Потеря ключа не позволит подписать совместимые обновления. Полный цикл «установить релиз → найти → скачать → установить следующий релиз» требует проверки на двух собранных версиях и до неё не считается подтверждённым.

GitHub Releases раздают файлы приложения и заметки выпуска, но не синхронизируют дневники. Для синхронизации используется отдельный Cloudflare Worker + D1; текущая передача дневника запускается вручную из «Настройки → Мои данные».

## Данные

- `%APPDATA%\Vyshe\journal.json` — активный дневник; `graphs\` — остальные графики.
- `deleted-graphs\` хранит удалённые графики для восстановления в течение 30 дней; `backups\` содержит ротационные резервные копии.
- `preferences.json` хранит запуск с Windows, запуск автозагрузчика в трее, проверку обновлений и завершение первого запуска.
- Избранные даты сохраняются в настройках самого дневника. Сводки недели/месяца вычисляются из записей и заметок, не добавляя данные в историю.

## Сервер и шифрование

Сервис синхронизации уже развёрнут на Cloudflare Free: Worker принимает зашифрованные на устройстве снимки и хранит их в D1. На каждом устройстве один раз импортируй один и тот же `cloudflare/local-credentials.json`, затем нажимай «Синхронизировать сейчас». Первая отправка требует подтверждения; при одновременных изменениях приложение предлагает выбрать локальную или облачную копию. Файл сопряжения содержит ключ и токен доступа — сохрани его отдельно и не загружай в GitHub. Детали и ограничения перечислены в `cloudflare/README.md`.
