# VYSHE — проверка перед выпуском

Связанный план: [PROJECT_PLAN.md](PROJECT_PLAN.md). Этот список — шаблон для следующего прогона, а не заявление, что всё ниже уже проверено. Выполненные проверки 1.7 описаны в [AUDIT.md](AUDIT.md). Будущие функции проверять после реализации.

Для каждого прогона записать версию/хеш EXE, ОС, размер окна, масштаб ОС/приложения, тему и вид графика. Статусы: PASS / FAIL / НЕ ПРОВЕРЕНО / НЕ ПРИМЕНИМО с причиной. Проверять на искусственном дневнике в отдельном VYSHE_DATA_DIR. Реальную историю не повреждать ради экспериментов.

## Короткая ручная проверка автора — после заметных изменений

- [ ] Создать график, выбрать тему, зайти в демо и вернуться: поля не потеряны, личные записи не смешались с демо.
- [ ] Добавить событие и заметку. Исправить событие, закрыть и открыть приложение: текст, дата, единица и итог сохранились.
- [ ] Выделять текст и отпускать мышь за пределами формы: форма не закрывается и не теряет ввод.
- [ ] Поменять тему и закрыть настройки без подтверждения: новая тема остаётся, в том числе после перезапуска.
- [ ] Вести мышью по пустоте, уровню, телу и тени свечи: карточка появляется только рядом со свечой; инструменты не перехватывают действия друг друга.
- [ ] Посмотреть 4ч на нескольких днях, увеличить колесом, переместить историю, нажать «Авто» и «К сегодня»: понятно, что произошло.
- [ ] Сменить вид графика и MA 7/14/28: отображение меняется, реальные итоги и записи прежние.
- [ ] Открыть заметку выбранного дня и без выбранного дня: дата явно видна и соответствует намерению.
- [ ] Перейти во второй график и обратно: события, заметки и инструменты относятся к своему графику.
- [ ] Экспортировать тестовую историю и импортировать в отдельный тестовый график: записи и итоги совпадают.

Если расчёты не менялись, достаточно одного простого события; остальные численные случаи проверяет автоматизация. Для сообщения об ошибке хватит шаблона в конце файла.

## P0 — данные и расчёты, обязательные условия выпуска

- [ ] База 1000, +5 баллов → 1005; база 1000, +5% → 1050; после изменения базы на 10000 процентная запись → 10500, балльная → 10005. Это два отдельных сценария.
- [ ] Последовательные +10%, −10% от 1000 дают 990; правка/удаление первого события пересчитывает следующие в правильном порядке.
- [ ] Ноль, отрицательный итог, дроби, очень малые изменения и предельные числа: нет NaN/Infinity и ложных процентов; недопустимый ввод отвергается с понятным сообщением.
- [ ] Несколько событий в одну минуту имеют стабильный порядок после перезапуска и переноса. При разных единицах итог не зависит от случайного порядка массива.
- [ ] Полночь, високосный день, граница недели/месяца/квартала/года, смена часового пояса и DST: пользовательская дата не сдвигается, события не теряются и не удваиваются.
- [ ] Любая агрегация OHLC сохраняет начальное и конечное значение; H ≥ O/C, L ≤ O/C. Пустая база не получает искусственную историю.
- [ ] Плавный ритм, HA, MA, зум, перемещение и смена темы не меняют исходные записи или экспорт. У сглаженного графика карточка не выдаёт визуальную разницу за вес реального события.
- [ ] Экспорт/импорт сохраняет UUID, единицы, заметки, кириллицу/emoji, настройки и tombstones; старые форматы мигрируют по документированным правилам.
- [ ] Плохой JSON, неподдерживаемая будущая схема, превышение размера, неверные типы/даты/числа не заменяют действующий дневник. Отмена файлового диалога ничего не меняет.
- [ ] Быстрое сохранение/переключение/закрытие, повторное нажатие и устаревшая ревизия не теряют подтверждённые записи и не смешивают графики.
- [ ] Прерывание процесса до/после атомарной замены файла; отказ доступа; нехватка места: после запуска доступно последнее подтверждённое состояние или явное восстановление. Нужен управляемый стенд/имитация, а не заполнение личного диска.
- [ ] Повреждённый журнал, резервная копия и неактивный график: понятная ошибка, сохранение исходных файлов, проверка резервной версии до замены.
- [ ] Будущий экспорт всей библиотеки: три графика туда-обратно, конфликт ID, ошибка на середине импорта, восстановление без частично заменённой библиотеки.
- [ ] Будущая отмена удаления возвращает событие/заметку и правильные последующие проценты; явно определено поведение tombstones.

Дополнить примеры генеративными проверками: валидные случайные последовательности, сохранение → загрузка, эквивалентность дневного итога календарной агрегации. Фиксировать seed ошибки для повторения.

## P1 — интерфейс и доступность

- [ ] Все шесть видов графика: попадание мышью по реальной геометрии, закрепление/снятие карточки, измерение, рисование и перетаскивание не конфликтуют.
- [ ] Границы панели и окна, прокрутка/зум при открытой подсказке: нет зависших карточек и перекрытого управления.
- [ ] Период MA запоминается; повторное включение возвращает выбранное число. Средняя и измерение объясняют, какие отображаемые значения используют.
- [ ] «Авто», стрелки, «К сегодня», переход к дате и смена интервала дают предсказуемый диапазон; нет недоступного состояния после крайнего приближения.
- [ ] Будущие сохранённые рисунки привязаны к координатам и своему графику, переживают перезапуск и согласованно переносятся.
- [ ] 100/125/150%, маленькое/большое окно, светлая/тёмная/своя тема: доступны кнопки, текст не перекрывается, для малых окон работает нужная прокрутка.
- [ ] Tab/Shift+Tab, Enter, Escape и стрелки: видимый фокус, логичный порядок, работа меню и возврат фокуса. Защищённая форма события сохраняет оговорённое поведение закрытия.
- [ ] Чтение названий и полей программой экранного доступа; цвет не единственный способ отличить рост от спада; контраст собственной темы проверен или есть понятное предупреждение.
- [ ] Уменьшенные анимации и быстрые движения мыши не вызывают мерцание/скачки; нет потери ввода при перерисовке.
- [ ] Каталог примеров: 500 уникальных текстов, перемешивание первого, поиск/категории, выбор без автоматической оценки и без отправки формы по Enter в поиске.
- [ ] «Сейчас» сохраняет актуальное время, пользовательское время не перезаписывается; дата заметки и события явно видна.

## Выпуск, производительность и открытый код

- [ ] Свежий portable EXE: холодная распаковка, старт без Node.js и сети, запись, перезапуск, экспорт/импорт через настоящие системные диалоги.
- [ ] Отдельные Windows 10/11 x64, обычная учётная запись; открытие второй копии приложения не повреждает историю.
- [ ] Обновление с предыдущей версии и старые фикстуры данных; документированный путь восстановления/отката. Не обещать совместимость старого EXE с новой схемой без проверки.
- [ ] 1k/10k/100k событий, 50k заметок, предельное окно: измерить время старта, записи, поиска, панорамирования, память и рост после длительной работы. Приложить машину и реальные числа, а не «работает быстро».
- [ ] Обработчики IPC, входящие файлы, разрешения, внешняя навигация и изоляция renderer проверены; аудит зависимостей разобран по применимости. Нулевой счётчик сканера не заменяет проверку кода.
- [ ] Репозиторий и архив не содержат личных дневников, тестовых профилей, секретов, node_modules и случайных файлов. Диагностика не содержит текста записей.
- [ ] LICENSE, уведомления о сторонних ресурсах, README, CONTRIBUTING, SECURITY, известные ограничения и CHANGELOG соответствуют выпуску.
- [ ] EXE соответствует проверенной сборке, версия в интерфейсе/пакете/имени согласована; CRC архива и SHA-256 проверены.
- [ ] Старые распространяемые сборки очищены по согласованной политике: первая, предыдущая резервная и текущая. Это не разрешение удалять дневники или их резервные копии.

## Текущие команды выпуска 1.9.9.13

Из корня исходников, после `npm ci`:

```powershell
npm test
npm run qa:tauri:layout
npm run pack
npm run qa:tauri
```

`npm test` содержит 87 проверок. Layout QA проверяет desktop и узкий экран в отдельном браузерном профиле; `qa:tauri` запускает Windows EXE в настоящем WebView2 с изолированным тестовым каталогом и проверяет сохранение, автозапуск в трей и повторное открытие.

## Шаблон ошибки

```text
Версия / ОС / масштаб / тема:
Вид графика / интервал (если относится к графику):
Шаги: 1. … 2. … 3. …
Ожидал:
Получил:
Повторяется: всегда / иногда (сколько раз из скольких)
Влияние: данные / расчёт / не могу выполнить действие / внешний вид
Скриншот или короткое видео: без личных записей
Минимальный искусственный пример: если необходим
```

Потеря данных, неправильный итог и невозможность открыть историю — блокирующие ошибки. Для них сначала сохранить копию повреждённого состояния, затем воспроизводить на копии. В отчёте различать проверенный факт, предположение о причине и ещё не проверенный сценарий.

Для 1.9.1: проверить отсутствие подсказки среди первых десяти общих идей, ровные колонки сводки, стабильность фразы при повторном клике и её смену после меню, плотность шкалы с MA и базой.

1.9.2: тонкая свеча выбирается вблизи, пустота вдали — нет; +/− и запятая, ноль и шаг 1, исправление ошибочного ввода; отрицательные баллы и проценты после сохранения; сумма и процент при ширине боковой панели 240px; группа до следующего события, выключение группы; монетка при создании, изменении, переключении и перезапуске.


## 1.9.3 — новые сценарии

- [ ] Знак виден в поле; −120%/−100% не записываются, +200% допустим; историческая правка с будущим дефицитом отклоняется. Старый отрицательный файл читается точно и допускает исправление.

- [ ] Минутный график после последней записи не пуст; через минуту живой край движется, прошлый период остаётся на месте.

- [ ] Базовая линия и уровни 25/50/75%; монетка с красным цветом, ободками, своими буквами; сохранность после перезапуска.
